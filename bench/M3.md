# M3 Benchmark - Middleware Pipeline

## Prediction before measuring

| Case | Prediction |
|---|---|
| `compose` with 0, 1, 5, 20, 100 no-op middleware | Cost increases with stack depth; the 20-middleware case remains small compared with HTTP and JSON work. |
| M3 at `LOG_LEVEL=warn` vs `info` | `info` is slower because access-log records are serialized and written for each finished response. |
| M3 plus 20 empty middleware | Some overhead, but less than enabling per-request info logging. |

## How to run

```powershell
node bench/pipeline.js
node bench/pipeline.js --http
```

The micro-benchmark warms up `compose` before timing 20,000 runs for each stack
size. The HTTP benchmark runs autocannon with 100 connections for 30 seconds
for each configuration. Its logger uses a no-op sink, so it measures level
filtering and JSON log construction rather than stdout or a production log
collector.

## Measurements

Measured on Node.js v22.12.0 / Windows 11. Each row is one run, so small
differences should be treated as noise rather than a stable ranking.

### compose micro-benchmark

Warm-up: 2,000 runs; measured: 20,000 runs per stack.

| No-op middleware | ns/run |
|---:|---:|
| 0 | 329 |
| 1 | 454 |
| 5 | 788 |
| 20 | 2,381 |
| 100 | 10,247 |

Twenty no-op middleware added about 2.1 microseconds to a `compose` invocation
in this run. The 100-middleware case makes the roughly linear dispatch cost
visible, but it is still small relative to network and application work.

### HTTP benchmark

Autocannon: 100 connections, 30 seconds per case.

| Configuration | req/s | p99 latency | Errors |
|---|---:|---:|---:|
| M2 bare HTTP handler (no pipeline) | 5,348 | 45 ms | 0 |
| M3 full pipeline, `LOG_LEVEL=warn` | 2,773 | 77 ms | 0 |
| M3 full pipeline, `LOG_LEVEL=info` | 2,715 | 75 ms | 0 |
| M3 plus 20 empty middleware | 2,810 | 71 ms | 0 |

The M3 cases use the same `/health` JSON response and middleware stack; their
logger sink discards output after serialization to avoid flooding benchmark
output. `info` was about 2% slower than `warn`, while the 20-empty-middleware
case was within run-to-run noise of the full warn pipeline. This benchmark does
not include the real stdout/log collector cost; M1 measured that access-log
output can cost substantially more. The bare M2 row is not an apples-to-apples
full-feature comparison: it quantifies the overhead added by the complete M3
stack rather than isolating just `compose`.
